# 模型调用效率与用量

角色正文继续使用各自的模型和私有记忆；以下优化不会把三名角色合并为一个模型回答。

## 上下文

- 人物回复按 token 预算保留当前频道的完整轮次。已入库历史按发送顺序追加，摘要轮换时才移动窗口起点。消息 ID 用于后端去重。
- 检索查询同时参考最新角色发言与最近用户话题，角色再次接话不会一直按用户的旧问题查找。
- 简短问候与确认通常跳过额外检索。其他普通聊天的附加记忆预算为1800字符；需回忆时为3000字符，其中最多1200字符先分给本轮关键历史证据。
- 普通角色回复的附加记忆使用 BM25；需要回忆时才尝试已配置的向量检索。归档事实可按事项标识和已核实原话匹配，因此「已经取消」也能通过原事项名称召回。群聊提示词逐条标注仅供角色参考的私聊记录。
- 最近少量跨窗口原文与相关历史参与检索，不再为了填满预算加入大量不相关旧消息。后端保留完整ID、知情范围和来源；模型看到来源窗口、时间、人物、正文、必要的行动关联和事实状态。
- 归档调用的原文按时间排序，以人物和正文发送；同批来源及时间范围只发送一次。原始消息ID、知情范围和备份完整保留在数据库。

## 减少额外调用

- 群聊仍逐条动态接话。明确向单人提问可直接给本人判断机会，仍能沉默；间接提及、多方问题和复杂情况交给公开调度模型。简短明确收尾可直接结束。
- 调度输入只带最近最多6条公开消息（合计4200字符）、600字符以内的话题起点、公开性格和必要状态，不加载角色私聊。
- 发送前只验证模型配置；直到角色确实获得接话机会才构建其完整记忆上下文。
- 场景每轮检查，有明确实际行动才调用维护模型；无变化保留已有状态。共享故事时间仍单独即时推进，不受这项过滤影响。
- 主动联系由人物安排下次考虑时间。未到期且无新互动不调用模型；到期后无变化仅携带较短近期原文。新用户互动可唤醒重新判断，执行租约只避免并发重复，并非消息频率限制。

## 重要事实

新归档可记录稳定事实key及active/completed/cancelled/superseded状态。明确变更需要本批原文证据才能将相同key的旧事实标记为已替代；旧事实和原文保留。检索排除已替代事实，取消/完成结果仍提供给模型，以免重新执行旧约定。旧字符串事实保持兼容，不能可靠关联的旧事实不会被猜测删除。模型提取与BM25检索仍可能漏配，近期明确纠正优先。

## 用量统计

访问运行中的 `/api/usage?days=7` 查看当前用户最近7天的分类统计，范围1–30天。

统计包括应用侧逻辑调用次数、失败次数、总耗时、输入/输出字符、供应商返回的输入/输出token和缓存命中token。SDK内部重试及流式usage兼容重试不单独展开为新的逻辑调用，耗时包含这些等待。没有返回usage的调用显示为缺少token用量，通过calls_with_token_usage区分；不会把字符冒充token。

`/api/usage` 的 `character_cache_by_model` 按角色实际使用的模型名称汇总。`hit_rate` 为缓存读取 token 除以总输入 token（0 到 1）；分子、分母均来自 `reported_calls` 中明确上报缓存字段的调用。供应商未报告命中数据时，`hit_rate` 为 `null`。

统计只保存数字、调用类型、模型名称及归属，不保存正文、密钥、接口地址或原始错误。数据后台每分钟批量写入chat_model_usage，正常退出补存，保留30天；本地SQLite迁移会复制这张表。进程崩溃可能丢失未落库统计，不影响已持久化聊天。

`MODEL_STREAM_USAGE=true` 默认请求标准流式usage；明确拒绝stream_options/include_usage的兼容接口会自动重试不带该选项。可设false跳过请求，字符与耗时仍统计。

## 辅助模型路由

群聊模型配置用于调度、场景维护和后台历史归档。角色发言、主动决策和角色私下交流继续使用各自私聊模型。回复时的窗口压缩使用该角色的模型，并以 context_summary 单独统计。

旧的 AUX_MODEL、AUX_BASE_URL、AUX_API_KEY 不再参与路由。具体规则见 CORE_OPTIMIZATION.md。

## 验证

`python -m unittest discover -s tests -q` 覆盖去重、权限隔离、短上下文、动态预算、最新角色检索、直接路由、场景过滤、事实变更、用量批量保存等。

真实模型测试均使用临时数据库：`tests/live_efficiency_check.py`、`tests/live_group_discussion_check.py`、`tests/live_fresh_start_check.py`、`tests/live_autonomy_check.py`。


输入建议（suggestion）使用当前故事中小婉私聊配置的模型、接口与密钥。


## 回复上下文预算

人物回复按固定规则与核心档案、冻结摘要、当前频道的已结束对话、最新事实与检索证据、当前轮次的顺序发送。跨窗口时间线放在动态部分，角色只能参考自己有权访问的记录。共同档案预算1000字符，个人档案预算1500字符。

历史超过可用预算的 90% 时，按完整轮次压缩最旧的一批消息，并尽量把剩余历史降到 55%。单批摘要最多处理约 3,600 token 的原文。摘要保存在按角色和频道隔离的会话资料里，按 800 token 总预算保留冻结的摘要段。原始消息留在数据库。摘要无法生成时使用有长度上限的原文摘录。遇到改期或取消，末尾的最新事实优先。

总输入预算由 CHAT_CONTEXT_INPUT_TOKENS 控制，默认 24576。CHAT_MODEL_CONTEXT_TOKENS 默认为 32768，部署时可按接口支持的模型窗口调整。实际输入上限还受输出预算和协议余量约束。默认用 tiktoken 的 o200k_base 估算，可通过 CHAT_CONTEXT_ENCODING 指定本地分词器。词表暂时不可用时使用偏保守的估算。超过必需输入预算的请求会提示用户缩短内容。精确用量以接口回报为准。

回忆时仍优先选最多 3 条相关证据。完成、取消及明确更新的状态能参与回答，同频道原文从动态补充中去重。

主页设置新增“用量”页，列出一次发送中的人物与调度调用，以及单独列出的后台/旧记录。既有用量没有发送标识，不能反推出完整归组；后台共享批次也单独显示。未返回用量时明确标注合计不完整，缓存命中 token 仍属于输入总量。数据库通过0003迁移增加可空 run_id，不修改聊天原文。
